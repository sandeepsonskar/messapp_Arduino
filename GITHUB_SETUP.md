# Publish this project to GitHub and build the APK

## 1. Create the repository

1. Sign in to GitHub and choose **New repository**.
2. Name it `mess-arduino-usb-bridge` (or another name you prefer).
3. Choose **Private** because this project contains your mess-management source code.
4. Do not initialize it with a README; this folder already contains project files.

## 2. Upload the files

Extract this ZIP. Upload the *contents* of the extracted `mess-arduino-github-repository` folder to the repository root. The `.github/workflows/build-android-apk.yml` file must remain in that exact location.

You can upload using GitHub's **Add file → Upload files** option in a desktop browser. For a large upload, use GitHub Desktop or Git.

## 3. Configure the Android app URL

Before building, edit:

`android-usb-bridge/app/src/main/java/com/vsipl/messbridge/MainActivity.kt`

Change `START_URL` from `https://YOUR_SERVER_IP:5443/scan` to the exact HTTPS URL printed by your Flask `run_local.py`, for example:

`https://10.2.4.22:5443/scan`

Use the current server IP, not the example if it has changed. Commit the change to GitHub.

## 4. Build the APK in GitHub

1. Open the repository's **Actions** tab.
2. Select **Build Android APK**.
3. Click **Run workflow** and confirm.
4. Open the completed run.
5. Under **Artifacts**, download `Mess-Arduino-Bridge-debug-apk`.
6. Extract the downloaded artifact ZIP; it contains `app-debug.apk`.
7. Transfer the APK to the Redmi 13 and install it. Android may ask you to allow installation from that source.

The workflow builds a debug APK. It is suitable for testing, not a signed production release. Keep the repository private and never commit database files, certificates, passwords, API keys, signing keys, or real student data.

## 5. Important network and certificate requirements

- Redmi 13 and the Flask server must be connected to the same LAN/Wi-Fi.
- The phone must be able to open the exact HTTPS `/scan` URL in its browser.
- The app intentionally does not ignore invalid TLS certificates. Install/trust the local CA certificate generated by the server on this dedicated supervisor phone, following `ARDUINO_INTEGRATION.md`.
- Android camera permission and USB permission must be granted.

## 6. First test

Test with a low-voltage indicator/load before connecting an actual door lock. Confirm that invalid, already-used, wrong-meal, wrong-mess and blocked QR codes do not energize the relay. Check relay active level and lock power/fail-safe behavior with a qualified installer.
